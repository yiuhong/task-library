One core, two modes

A wired task is one script, assets/tasks/<id>.js. The gamified page and the classical page both load that script. The shell paints the frame, the type, and the buttons. It does not build the trial list, choose the stimulus, or score the response.

Mode is classical or gamified. ?mode=classical and ?mode=gamified select it and store the choice in this browser under project-trial:mode. With no mode in the address, the stored choice is used. If nothing is stored, the task opens gamified.

Classical uses a mid-gray field, about #7f7f7f, and Arial. Gamified uses the dark Trial theme. Points, badges, sounds, and motion are chrome. On a wired task they do not change the stimulus, the scheduled intervals, the randomisation, or the score. Where a shell still shows a word after a response, the task note below says what that word is.

How to run a protocol

  1. Open the device check on the computer you will use. It is a short hub. Refresh, setTimeout lateness, the performance.now() step, and the page-clock flashes are separate pages. Each page gives a pass, fail, or could-not-run verdict and can download its own JSON. Leave the tab visible while a check runs. This site does not keep the file.
  2. Open the task. Choose classical or gamified on the welcome screen before the scored block.
  3. Read the methods note for that task. Classical is the quieter main block. Gamified runs the same trials and the same scoring, and it can show a brief outcome after the response has been stored.
  4. Practice rows are marked practice and stay in the file. They are left out of the results-screen totals. On visual working memory, Skip to Main drops the practice log and starts the 36. Brightness has no practice block. Spatial Go/No-Go includes practice only when that option is on.
  5. Finish the main block. On the results screen, press Download CSV and Download JSON. The file is written because you pressed the button.
  6. The browser also keeps the latest finished run in localStorage on this device. A later finished run replaces it. Take the download with you. Clearing site data in the browser removes the local copy.

There is no participant list here. Consent, identifiers, and any server you use belong in your own protocol. The files are not sent back to this site. It has nowhere to put them.

Export

Wired tasks share assets/trial-export.js. The JSON schema is project-trial.export.v1. The wrapper has taskId, mode, libraryVersion, exportedAt, params, summary, and trials. libraryVersion is the version string already printed in the footer. This page does not move that number.

params is a snapshot of the task’s counts, timings, stimuli, response map, and the feedback policy of the shell that ran. summary repeats the numbers the results screen already computed. Trial fields use the CSV headers. The CSV repeats the snapshot in params_json on every row so the sheet stands alone. The JSON keeps params once.

Shared columns, in this order
Column What it is
task_id The task id: vwm, flanker, stroop, oddball, gonogo, orbital_gonogo, brightness, numerosity, rdk, corsi, or bandit.
mode classical or gamified.
params_json The parameter snapshot, on every CSV row. Omitted inside each JSON trial because params is on the wrapper.
trial_index 1-based index across practice and main in that run.
block practice or main.
stimulus A short description of what that trial showed.
condition The task’s condition label for that trial.
response The choice. A flanker or numerosity or RDK trial that passed the window stores timeout. An oddball withhold stores withhold. A go / no-go trial with no press stores NONE.
accuracy 1 or 0, using the score the results screen already uses.
rt_ms The millisecond value that task already averages, rounded the same way. Blank, and JSON null, when that task already leaves the time blank. The task note says which trials those are.
timestamp Wall-clock time when the response was stored, ISO 8601.
onset_perf_ms performance.now() when the scored stimulus was shown. The origin is this page load, near zero, and is a page clock.
response_perf_ms performance.now() when the response was stored, or when the response window closed.

Task columns follow those, in the order the task first records them. A missing task field is blank in the CSV and null in JSON. onset_perf_ms and response_perf_ms let you recompute the difference. rt_ms is the rounded difference the score uses, so the two can disagree by less than a millisecond.

Browser timing

These tasks schedule their intervals with setTimeout. That clock is not locked to the display. Response time is a difference of two performance.now() readings: one in the function that shows the scored stimulus, and one in the input handler. The first stamp is when the page asks for the paint. It is earlier than the moment the pixels change, and earlier than the light reaching the eye. The second stamp is when the handler runs. It is later than the switch in the keyboard or the finger on the glass.

A hidden tab can delay timers. Another monitor, another browser, or a busy machine can change the same protocol. The device check reads this tab at this moment, one check per page. Each page states its rule of thumb and writes the same thresholds into the JSON. The reading stays with the person who downloads it. It does not transfer to the next machine, and it does not stand in for a light sensor or a calibrated button box.

Report the numbers as browser measurements. A photodiode study, if you run one, is a separate record.

Gamified mode

The gamified shell is the same trial loop in a different frame. It can be the right shell when a gray page would lose the person you need to test, or when the shell itself is what you want to study. The cost is an outcome cue after some trials. The cue is drawn after that trial’s response has been stored. It does not rewrite the trial list, the stimulus, or the score. It can change how the person meets the next trial.

Wired tasks keep a running score and a running mean RT off the screen during the trial, in both shells. A short word after the trial, or a summary after the block, can still appear. The notes below say which words appear. For a main block without those words, choose classical. The timer limits above apply to both shells.

Visual working memory

Play from the gamified shell or the classical shell. Colored squares with a same or different probe are the display in Luck and Vogel (1997), doi:10.1038/36846. Cowan's K follows Cowan (2001), doi:10.1017/S0140525X01003922. Pashler's K follows Pashler (1988), doi:10.3758/BF03210419. Counts and timings are on the parameters page. The download uses those formulas.

Response time starts when the probe is drawn. The 500 ms fixation, 250 ms sample, and 900 ms delay sit in the parameter snapshot, and they sit outside rt_ms. condition is SAME or DIFFERENT. set_size is 4, 6, or 8. items_json holds the squares. Positions in the file are rounded to 0.001 canvas unit. The canvas drew the unrounded values.

hit, false_alarm, miss, and correct_rejection follow the results screen: a different trial is the signal, and the answer “different” is a hit or a false alarm. cowan_k and pashler_k copy the set-size estimates from the main block onto each main trial of that set size. Practice rows leave them blank. A single trial does not receive its own K. The headline mean on the screen is summary.meanCowanK. The overall helper is called without a set size, so its own K fields stay 0. Use bySetSize.

After the choice is stored, the gamified shell turns the fixation green or red and shows the word and the response time for the 500 ms interval. Classical keeps a dark fixation. Classical practice can show Correct or Incorrect, without the response time. Classical main shows no word. The interval is 500 ms in both shells. For a main block without the color and the word, use classical.

Eriksen flanker

Play from the gamified shell or the classical shell. The arrow array, the 6 practice trials, the 36 main trials, and the Eriksen and Eriksen (1974) note, doi:10.3758/bf03203267, are on the parameters page. This demo already uses arrows. The download does not change that.

condition is congruent, incongruent, or neutral. stimulus is the five-character array. fixation_ms is the fixation that was drawn, sampled from 400 ms through 600 ms. Response time starts at array onset and does not include fixation. A timeout stores a blank rt_ms, timed_out 1, and accuracy 0. The results screen still treats that trial as incorrect and leaves it out of the mean correct RT. The conflict effect in summary is still incongruent mean correct RT minus congruent mean correct RT.

The header slots for running accuracy and mean RT are hidden in both shells. The trial counter and the progress bar stay. They are not a score. After the response is stored, the gamified shell shows TOO SLOW, CORRECT, or INCORRECT for the 400 ms hold, with the response time or the target side underneath. Classical practice shows a short word and no response time. Classical main shows no word. The hold and the 350 ms blank still run, so the gap from one array to the next is the same. The gamified word can affect the next trial. For a main block without it, use classical.

Stroop Dash

Play from the gamified shell or the classical shell. The colored color-word, the Stroop (1935) note, doi:10.1037/h0054651, and the counts are on the parameters page. The main block is 20 trials in both shells. Classical adds 8 practice trials with the same builder.

condition is congruent or incongruent. stimulus is the word and the ink, such as RED/#44ff44. rt_ms is the unrounded time from the colored word, including a timeout. The mean on the screen still uses correct trials only. accuracy is 1 or 0. Task columns are trial_in_block, word, ink, correct_key, and the orientation at the response. summary repeats accuracy, the two condition means, and the interference difference the sentence uses. The gamified score and max combo are included when that shell computed them.

After the row is stored, the gamified shell shows PERFECT!, OOF!, or TOO SLOW! for the existing 400 ms hold. Classical practice shows Correct, Incorrect, or No response. Classical main shows no word. The hold and the 300 ms blank still run. Live score, combo, accuracy, and mean RT are hidden in both shells. The word is not set on fire, and the page is not recolored from the combo. For a main block without the word, use classical. The welcome button Saved sessions CSV is the older multi-session log. The results buttons are this run.

Oddball

After the row is stored, the gamified shell shows CAUGHT IT!, GOOD, MISS!, or FALSE ALARM! for the existing 300 ms hold. Classical practice shows Correct, Incorrect, or No response. Classical main shows no word. Live score, combo, accuracy, and mean RT are hidden in both shells. The shape is not set on fire. For a main block without the word, use classical.

Go / No-Go

Play from the gamified shell or the classical shell. The 8 practice trials, the 40 main trials, and the windows are on the parameters page. No additional citation was added.

condition is GO or NOGO. stimulus is GO LEFT, GO RIGHT, or NOGO. response is LEFT, RIGHT, or NONE. rt_ms is the rounded time on a press and blank when the window closes with no press. accuracy is the correct flag the results screen already uses. summary repeats go accuracy, mean go RT, commission, and omission for the main block. The GO badge, the NO-GO mark, and the shrinking deadline bar stay. They are the stimulus, not a score. The header shows the block and the trial count.

After the row is stored, the gamified shell shows HIT, WRONG SIDE, FALSE ALARM!, TOO SLOW!, or WITHHELD for the existing 400 ms hold, with the subtitle it already used. Classical practice maps those to Correct, Incorrect, or No response. Classical main shows no word. The hold and the blank from 250 ms through 450 ms still run. For a main block without the word, use classical.

Spatial Go/No-Go

Play from the WebXR page. This task is not on the shared shell. The hub card has no Classical link, and the page does not read or write project-trial:mode. ?mode=classical does not restyle the scene, the timings, or the score. It turns off the floating outcome words and their sounds. Any other address, including no mode, keeps those words. Counts, planes, and the size and fixation choices are on the parameters page. No citation was added, and no light-sensor check was added.

The file uses task id orbital_gonogo and mode gamified unless the address is ?mode=classical. condition is GO or NOGO. stimulus is the type and the plane, such as GO near. accuracy is 1 for a hit or a correct rejection and 0 for a false alarm or a miss. rt_ms is the rounded time on a trigger and blank when the window closes with no trigger. A click that misses the object is not a response. onset_perf_ms is when the page asks A-Frame to add the target. That is earlier than the pixels and earlier than the light. In a headset it is also earlier than the frame that shows the object. The 1200 ms window is setTimeout. Task columns keep the fields the old CSV already stored, including depth, position, radius, outcome, and the running score after that trial. summary repeats the hit rate, false-alarm rate, mean go RT, and the by-depth table from the results screen, plus the final score.

The running score and streak are hidden during the run. The trial counter stays. The floating word is drawn after the row is stored, during the existing 800–1400 ms gap before the next target. It can affect the next trial. ?mode=classical is how to leave that word, and its sound, off. Practice rows stay in the file when practice is on, and they are marked practice. They are not in the rates on the screen.

Brightness detection

Play from the gamified shell or the classical shell. The 40 trials and the four conditions are on the parameters page. There is no practice block, and neither shell says whether the choice was right. No citation was added.

condition is LL, LH, HL, or HH. stimulus is the two gray levels. rt_ms is the rounded choice time, blank on a timeout. confidence, confidence_key, and confidence_rt_ms are the rating the trial already stored. Numerosity comparison

Corsi span

Play from the gamified shell or the classical shell. The warmup, the staircase, and the flash timings are on the parameters page. No citation was added. The span counter and the trial counter stay. There is no running accuracy.

condition is the span, such as span-3. stimulus is the target sequence. response is the tapped sequence. rt_ms is the mean inter-tap latency the results screen already averages. total_rt_ms is the last tap minus the go cue. summary repeats max span, correct sequences, block score, the product, and that mean. Practice rows use block practice.

After the sequence is stored, the gamified shell shows CORRECT SEQUENCE or INCORRECT SEQUENCE during the existing 900 ms pause. Classical practice shows Correct or Incorrect. Classical main shows no banner. For a main block without the banner, use classical. Sequence tones stay off in classical, as they already were.

Reversal learning

Play from the gamified shell or the classical shell. The 6 practice trials, the 48 main trials, and the reversal rules are on the parameters page. No citation was added.

accuracy copies chose_optimal. It is the better-option flag on that trial, not a Correct or Incorrect judgment. A rewarded suboptimal trial is accuracy 0 and reward 10. condition is the reversal phase, such as phase-0. stimulus is the left and right symbols. response is left or right. rt_ms is the rounded time from the cards. summary repeats the points, reward rate, better-option rate, win-stay, lose-shift, perseverative count, reversals, and mean RT from the results screen.

The payoff is shown after the choice is stored, during the existing 750 ms feedback, on practice and on the main block, in both shells. It is +10 or +0. That number is the reward, so neither shell removes it. The live point total is hidden in both shells. The trial counter stays. There is no shell that turns the payoff off.

Validation roadmap

First, the machine. Open the device check and run each page on every computer you mean to use, with the tab visible, and keep the JSON with your protocol notes. The refresh page estimates the animation-callback rate. The timer page reports how late setTimeout was relative to the delay the page asked for. The clock page reports the step this page saw from performance.now(). The flash page reports the page clock from the color change to your own key or click. Each page marks pass, fail, or could not run. Those files support a decision about whether the machine is worth using. They do not clear the machine for a methods section on their own.

Later, human data. A light sensor on the glass, or a calibrated button box, on a few of those machines, is the check this site cannot run. A separate study can then compare a known effect, such as the flanker conflict or change-detection K, with the published pattern. This page does not run that study and does not collect those trials.
