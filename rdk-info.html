RDK Motion Coherence

A circular cloud of dots drifts left or right. Judge the net direction. Six practice trials come before the 36-trial main block.

What it shows

Each trial shows a fixation cross, then 150 white dots inside a circular aperture. Some dots move together left or right. The rest move at random. Coherence is easy (40%), medium (20%), or hard (8%). The main-block summary reports accuracy, mean response time, and median response time, plus the same accuracy and mean time at each coherence.

The gamified shell says correct, incorrect, or timeout after each trial. This is a teaching demo, not a clinical or normed test.

Parameters

Practice
6 trials. One trial for each coherence and each direction, then a shuffle.
Main block
36 trials. Six trials for each coherence and each direction, then a shuffle.
Dots
150 dots, radius 2.2, on a 320-unit canvas. The aperture radius is 148. Coherent dots are round(150 × coherence): 60, 30, or 12. Each dot lives 24 frames, then is replaced, so one dot cannot be followed for the whole display. Speed is 165 pixels per second. If the browser asks for reduced motion, speed is 85.
Fixation
500 ms. A central cross. The choice is not open yet.
Motion
Dots move for up to 800 ms. A response is accepted from motion onset. Response time starts there.
Choice window
1200 ms from motion onset. After 800 ms the moving dots stop and the cross remains until the window ends. A timeout is incorrect, stores an empty response time, and is left out of the mean and median. Incorrect choices that were answered are included in those times.
Feedback
400 ms, then a 350 ms blank. Those two durations are the same on the classical shell. On the gamified shell, sound is on at the start and SFX turns the tones off. The classical shell plays no tones and does not write the shared mute key. See Shells.
Repeat practice
Drops the in-memory log and runs the 6 practice trials again. Begin Main Block starts the 36. Run New Session starts practice over.

Shells

The same motion-coherence core runs in two shells. RDK Motion Coherence is the gamified shell. A missing mode, or any mode other than classical, plays that shell as it does today: CORRECT, INCORRECT, or TOO SLOW after every practice trial and every main trial, the response time under that word, tones (including the fixation chirp), and the SFX control. Classical motion coherence is the quiet lab shell. The page around the aperture is mid-gray. Dot color, count, coherence, speed, and the aperture stay the same.

Both shells use the same 6 practice trials and the same 36-trial main block. Classical does not add a practice block and does not drop the one this task already has. That is the exception to Classical Stroop, which inserts extra practice. Classical practice shows only Correct, Incorrect, or No response. There is no millisecond subtitle and no tone. The main block shows no words and plays no tones. The 400 ms feedback hold and the 350 ms blank still run, so the timing does not change. During a trial, accuracy and mean response time are hidden. The block and trial index stay. The end screen is the summary in both shells: main-block accuracy, mean response time, median response time, and the coherence breakdown. There is no arcade score. The SFX control is hidden in the classical shell and does not write project-trial:sfx.

How to play

  • Look at the center of the circle. Choose the net direction of the dots.
  • Left pad, A, or Left Arrow means left. Right pad, L, or Right Arrow means right. A pad press and a key call the same choice.
  • A held key does not answer again. One choice is accepted while the trial is waiting for a response.

Data

When the main block finishes, this browser stores one payload under the localStorage key projectTrial_rdk_v1. A later finished run replaces that payload. Nothing is uploaded. There is no Clear saved control. The payload gains a mode field, gamified or classical.

Download Trial CSV writes the current run as a file on the device. Columns are trial, block, coherence_pct, direction, response, correct, rt_ms, timestamp, and mode (gamified or classical). Mode is the last column. The columns before it stay in this order. The file name is rdk_motion_data_ plus a timestamp. The page does not log orientation turns.
