Device check

A support step on this tab, before you run a task. It reads this browser at this moment. It is not a study. It is not a photodiode or light-sensor validation. Nothing is uploaded.

Five checks

Each check is its own page. Each page has a run control, a pass or fail mark, the numbers, a plain-language interpretation, and a JSON file you can download. Run a check with this tab in front of you. A hidden tab will slow the timers, and a refresh sample taken in the background is discarded. The headset check asks for an immersive-vr session, so a computer with no headset cannot run it. The numbers describe this moment. Run the checks again on each machine you care about. The file stays on this computer.

  • Refresh estimate. How often requestAnimationFrame called back. The sample is 120 frames, and the first 5 intervals are left out.
  • Timer lateness. setTimeout delays of 0, 16, and 50 ms, five times each.
  • Clock step. The step of performance.now() in a tight loop.
  • Page clock. Five flashes. The time from the frame callback to a key or a click.
  • Headset. Whether navigator.xr can start and end an immersive-vr session, which reference spaces are available, and which input sources appear. For Spatial Go/No-Go.

How a verdict is marked

These are conservative rules of thumb for a browser tab, not a lab certificate. The rule for each check is written on that page and copied into the JSON. The mark is an icon plus words, so the result does not depend on color.

  • Pass. The check finished and met the rule on that page.
  • Fail. The check finished and did not meet the rule on that page.
  • Could not run. The tab was in the background, you stopped a run, or the browser lacks the API. On the headset page, a desktop or phone that does not offer immersive-vr is also could not run. This is not a machine fail.

The download schema is project-trial.device-check.v2. Each file names the check, the library version, this browser, the measurements, the verdict, and the thresholds. verdict is pass, fail, or could_not_run. The headset check uses that same file shape, so the schema version is unchanged.

What these pages can and cannot stand behind

  • The refresh estimate is how often requestAnimationFrame ran while this tab was visible. It can be lower than the rate printed on the monitor. It is not when the pixels changed. A light sensor on the glass would be required to time the pixels. This site does not use one.
  • setTimeout is not a vertical-blank interrupt. The scored two-dimensional tasks schedule fixation, stimuli, and the gaps between trials from display frames. Spatial Go/No-Go still uses setTimeout for its 1200 ms window. The timer page reports how late a setTimeout callback was compared with the delay this page asked for.
  • performance.now() is a monotonic page clock. Its origin is the page load. A small step is not proof that a stimulus lasted that many milliseconds on screen.
  • The page-clock number ends when the input handler runs. It includes your movement. It leaves out the display lag and most of the device lag. Do not enter it as a participant’s reaction time. If event.timeStamp uses another origin, the handler gap is left blank.
  • A background tab, a busy processor, or a low-power setting can move every number. Repeat the check on the machine and the browser you will actually use.
  • The headset check can start an immersive-vr session only in a browser that offers one. A desktop or phone without a headset is could not run. A session that starts without the local-floor space Spatial Go/No-Go requests is a fail. Seeing no controller is not a fail by itself.
  • The download is a JSON file you choose to save. This site does not receive it. The check does not open a task, does not score a person, and does not ask for consent because it is not a study.
