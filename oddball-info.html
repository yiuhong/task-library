Oddball Dash

A short teaching demo of rare-target detection. Withhold on the frequent shape. Respond only to the rare one.

What it shows

Most trials are a cyan O. A few are a pink X. Letting a standard pass is correct. Pressing on a standard is a false alarm. Missing the X is a miss. The results screen reports standard accuracy and the mean time to catch an oddball.

The score and combo are part of the demo. They are not a clinical or normed measure.

Parameters

Trials
30. Oddball rate 0.2, so floor(30 × 0.2) = 6 oddball and 24 standard. The gamified shell has no practice block.
Standard
Character O, color #06b6d4. Correct action is to do nothing.
Oddball
Character X, color #ec4899. Correct action is the J pad or the J key.
Order
Fisher–Yates shuffle, then the first two trials are forced to standards so the run starts on the frequent shape.
Fixation
300 ms. A slate plus sign, #475569.
Response window
1200 ms. When it ends with no press, a standard is correct and an oddball is a miss.
Between trials
Feedback stays 300 ms, the shape clears, then a 400 ms blank.
Scoring
Oddball hit: max(0, 1200 − rounded RT) plus 500 × (1 + combo × 0.1). Correct withhold: 50 × (1 + combo × 0.1). Both use the combo from before it increases. A miss or false alarm sets combo to 0 and adds nothing.
Accuracy
Correct trials divided by all trials so far. Withholds, hits, misses, and false alarms all count.
Speed
The HUD and the results card use the mean RT of oddball hits only. Withholds do not have a response time. The score on screen is rounded to the nearest point.

Classical presentation

The welcome and results screens have a Gamified | Classical control. The choice is stored in this browser as project-trial:mode. ?mode=classical still opens the lab shell.

No single oddball paper was re-checked for this shell. The lab screen keeps this demo’s stimuli: frequent O in #06b6d4, rare X in #ec4899, the same rate and timings. It drops the dash title, score, combo, glow, shake, and reward tones. Press J for X. Do nothing for O.

Shells

The same Oddball core runs in two shells. Oddball Dash is the gamified shell. Classical Oddball is the quiet lab shell on a mid-gray canvas. It uses the same main block: 30 trials, floor(30 × 0.2) = 6 oddball and 24 standard, the same shapes, the J key, and the same timings, without score, combo, shake, fire, or reward sounds. During a trial it does not show accuracy or response time. The trial counter stays. Its label says Practice during practice and Trial during the main block.

Classical starts with 10 practice trials from the same generator, so floor(10 × 0.2) = 2 oddball and 8 standard, and the first two trials are standards. Practice runs straight into the main block, with no extra click. Practice shows Correct, Incorrect, or No response for the 300 ms hold. No response is a timeout on an oddball. A correct withhold is Correct. A false alarm is Incorrect. A hit is Correct. That line does not include response time, and it does not use the gamified words. The main block shows no words after a trial. The 300 ms hold and 400 ms blank still run. Practice is saved with block = practice and is left out of the end screen. That screen hides the score and reports standard accuracy, oddball speed (mean response time of oddball hits), and overall accuracy for the 30 main trials. The sentence is plain and does not include max combo. The scoring row above describes the gamified shell only. Saved rows include mode (gamified or classical).

How to play

  • Tap the J pad or press J only when the pink X appears. Pads call the same response path as the keyboard.
  • The key is not case-sensitive. A held key does not answer the next trial. Ctrl, Cmd, and Alt chords are ignored.
  • One response is accepted per trial, and only while the shape is on screen. Other keys do nothing.
  • A tap is counted once. A click that follows the same press within 750 ms is ignored.

Data

Each run is saved in this browser under the localStorage key project-trial:oddball. Refreshing, leaving, or closing the tab keeps it. Play again appends another session and does not resume an unfinished one. Nothing is uploaded. The browser keeps the newest 100 sessions for this task.

Download CSV writes every saved session as a file on the device. Columns are trialNum, type, responseKey (j or withhold), rt (empty when the response was a withhold), isCorrect, orientationType, orientationAngle, orientationAt, orientationTMs, orientationReason, record, sessionId, startedAt, endedAt, complete, and mode (gamified or classical; blank on sessions saved before that field). A classical download adds block (practice or main). Trial numbers restart at 1 in each block. The gamified download does not add that column. Trial rows use record = trial. The file name is oddball_dash_data_ plus a timestamp.

Portrait and landscape both run. The page never locks the device direction. Each trial row stores the orientation at the response. Extra CSV rows with record = orientation are the session turns: start, each change, and end, with ISO time (orientationAt) and orientationTMs (milliseconds from performance.now()). A short note appears if you rotate, and the task keeps going. The results screen reports the starting orientation and how many turns were logged.

Clear saved removes project-trial:oddball from this browser. It asks for a second click. The on-screen summary stays until you leave the results screen. Download before you clear if you still want the file. Play again returns to the welcome screen, and the max combo resets.
