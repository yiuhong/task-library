How to respond

Each demo has large pads and a matching key. A tap and a keypress call the same response path. One response counts per trial. Holding a key does not fire the next trial.

Data

Nothing is uploaded. Stroop Dash, Oddball Dash, and Brightness Detection each keep their runs in localStorage on this browser and can download a CSV of those trials, including orientation start and turn rows. Clear saved removes that browser copy. Refresh does not. Numerosity Comparison, RDK Motion Coherence, Eriksen Flanker, Visual Working Memory, Go / No-Go, and Reversal Learning each keep the latest finished run under their own key (projectTrial_numerosity_v1, projectTrial_rdk_v1, projectTrial_flanker_v1, projectTrial_vwm_v1, projectTrial_gonogo_v1, projectTrial_bandit_v1) and can download a CSV of that run. A later finished run replaces it. Corsi Span appends each finished run to a list under projectTrial_corsi_v1. Those tasks have no Clear saved control and do not log orientation turns.

Portrait and landscape both run. Hub demos do not lock orientation. On Stroop, Oddball, and Brightness, each saved trial includes the orientation at that moment, and turns during the run are timestamped on the session log. See each task’s parameters page for where that log lives.

Scores are for teaching. They are not a clinical assessment.

Look and future demos

Shared colors, type, pad chrome, and HUD spacing live in assets/trial-theme.css. A new demo can link that file and override the variables it cares about. The helpers are optional, so a demo can still invent its own controls and stimulus layout.
