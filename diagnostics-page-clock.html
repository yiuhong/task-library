The rule on this page

The millisecond value is not scored.

  • Pass only if all five flashes got a press, a key or a click, and returned a page-clock number.
  • Fail if any flash was missed, or if a flash did not return a number.
  • Could not run if you stop before five flashes finish, if this tab is hidden, or if the browser has no requestAnimationFrame. A hidden tab stops the remaining flashes. That is not a machine fail.

Each flash waits 500 to 900 ms, then the next animation frame turns the square light. The response window is 3000 ms.

Run this check

Leave this tab visible. Wait for the square to turn light, then press any key or click the square. Escape stops the run.

Interpretation

The page clock is the time from the animation-frame callback that turns the square light to the key or click handler. It includes your movement. It leaves out the display lag and most of the device lag. Do not enter this number as a participant’s reaction time.

About these browser hints

navigator.deviceMemory, when the browser sends it, is a coarse bucket, often capped. The CPU value is a hint. The storage line is a one-key probe: the page writes project-trial:device-check-probe, reads it back, and removes it. Verdicts are not stored. Trial rows are not stored here.

Limits of this number
  • The page-clock number ends when the input handler runs. Time in the keyboard, touchscreen, operating system, and the display is outside it. If event.timeStamp uses another origin, the handler gap is left blank.
  • The download is a JSON file you choose to save. This site does not receive it. The check does not open a task, does not score a person, and does not ask for consent because it is not a study.
  • It is not a study. It is not a photodiode or light-sensor validation.
